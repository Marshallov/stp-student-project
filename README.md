## Требования

Для запуска приложения без Docker установите:

- **JDK 25** — именно эта версия Java указана в `pom.xml`. Нужен JDK, а не только JRE.
- **Apache Maven 3.9 или новее**.
- **PostgreSQL 16** (подойдёт и более новая совместимая версия).
- **Node.js 22** и npm для запуска React-интерфейса.
- Git — чтобы получить исходный код из репозитория.

Ссылки на официальные инструкции:

- [Загрузка JDK](https://jdk.java.net/25/)
- [Установка Apache Maven](https://maven.apache.org/install.html)
- [Загрузка PostgreSQL](https://www.postgresql.org/download/)
- [Загрузка Node.js](https://nodejs.org/)
- [Git](https://git-scm.com/downloads)

После установки проверьте версии в терминале:

```bash
java -version
javac -version
mvn -version
node --version
npm --version
psql --version
```

Для Java и компилятора должна отображаться версия 25. В выводе `mvn -version` Maven должен использовать именно этот JDK.

## Запуск без Docker

В этом варианте PostgreSQL, backend и frontend запускаются как три локальных процесса. База данных должна быть запущена до старта backend.

### 1. Получите исходный код

```bash
git clone https://github.com/Marshallov/stp-student-project.git
cd stp-student-project
```

Если проект уже скачан архивом или через Git, откройте терминал в корневой папке проекта — там, где находятся `pom.xml` и папка `frontend`.

### 2. Создайте базу и пользователя PostgreSQL

Убедитесь, что служба PostgreSQL запущена. Создайте отдельного пользователя приложения и базу данных. Откройте `psql` под администратором PostgreSQL, например:

```bash
psql -U postgres
```

В командной строке `psql` выполните:

```sql
CREATE ROLE student_app WITH LOGIN PASSWORD 'change-this-password';
CREATE DATABASE students_db OWNER student_app;
\q
```

Замените `change-this-password` на свой пароль и сохраните его — он понадобится для запуска backend. Если база или роль уже существуют, повторно создавать их не нужно. Подключение настраивается переменными окружения на следующем шаге.

При первом подключении приложение автоматически создаст в базе схему `students_schema`, таблицы, тестовые аккаунты и демонстрационные записи студентов. Удалять базу для повторных запусков не нужно.

### 3. Запустите backend

В первом терминале, из корневой папки проекта, укажите параметры подключения и запустите Spring Boot.

**macOS или Linux (Bash/Zsh):**

```bash
export SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/students_db
export SPRING_DATASOURCE_USERNAME=student_app
export SPRING_DATASOURCE_PASSWORD=change-this-password
mvn spring-boot:run
```

**Windows (PowerShell):**

```powershell
$env:SPRING_DATASOURCE_URL = "jdbc:postgresql://localhost:5432/students_db"
$env:SPRING_DATASOURCE_USERNAME = "student_app"
$env:SPRING_DATASOURCE_PASSWORD = "change-this-password"
mvn spring-boot:run
```

Не закрывайте этот терминал: в нём работает backend. При успешном запуске API доступно по адресу `http://localhost:8080`. Параметры подключения и порт можно переопределить переменными окружения; значения по умолчанию описаны в `src/main/resources/application.yml`.

В репозитории есть скрипты `mvnw` и `mvnw.cmd`, но нет конфигурации Maven Wrapper (`.mvn/wrapper/maven-wrapper.properties`). Поэтому для запуска используйте установленный Maven и команду `mvn`, а не `./mvnw`.

### 4. Запустите frontend

Откройте второй терминал:

```bash
cd frontend
npm ci
npm run dev
```

`npm ci` устанавливает зависимости из `package-lock.json`; обычно эту команду нужно выполнить только при первой настройке или после изменения зависимостей. Не закрывайте терминал, пока пользуетесь приложением.

Откройте в браузере адрес, показанный Vite (по умолчанию **http://localhost:5173**). Запросы frontend с путём `/api` автоматически перенаправляются на backend `http://localhost:8080`, поэтому в обычном локальном запуске отдельно настраивать CORS или URL API не требуется.

### 5. Войдите в приложение

Для первого входа используйте один из автоматически создаваемых локальных аккаунтов из таблицы [Тестовые аккаунты](#тестовые-аккаунты). Они предназначены только для разработки и демонстрации; не используйте эти пароли в доступном из интернета окружении.

### 6. Остановите приложение

В каждом терминале, где выполняется backend или frontend, нажмите **Ctrl+C**. PostgreSQL можно оставить запущенным или остановить штатными средствами вашей операционной системы.

## Тестовые аккаунты

При первом запуске приложения автоматически создаются эти учётные записи:

| Email | Пароль | Роль | Что можно проверить |
|---|---|---|---|
| `superadmin@example.com` | `superAdmin` | `SUPER_ADMIN` | Просмотр и управление командой и ролями |
| `admin@example.com` | `admin` | `ADMIN` | Просмотр, добавление, изменение и удаление учеников |
| `teacher@example.com` | `teacher` | `TEACHER` | Просмотр карточек учеников |

В чистой базе также создаются пять демонстрационных учеников. Эти учётные данные предназначены только для локального тестирования — не используйте их в опубликованном окружении.

## Тесты и покрытие JaCoCo

Для запуска unit-тестов, проверки минимального покрытия строк 80% и генерации отчётов выполните из корневой папки проекта:

```bash
mvn clean verify
```

Запущенная команда компилирует backend, выполняет тесты и завершится ошибкой, если покрытие строк окажется ниже 80%. Для проверки unit-тестов PostgreSQL запускать не требуется.

Отчёты JaCoCo создаются после успешной сборки:

- HTML: `target/site/jacoco/index.html`
- XML: `target/site/jacoco/jacoco.xml`

HTML-отчёт можно открыть браузером. Если вы меняли исходный код или тесты, выполните `mvn clean verify` повторно, чтобы сформировать свежий отчёт.

## Запуск через Docker Compose

Установите и запустите Docker Desktop, затем в терминале перейдите в корневую папку проекта. Docker Compose скачает необходимые базовые образы, соберёт frontend и backend, запустит PostgreSQL и приложение:

```bash
docker compose up --build -d
```

Дождитесь, пока база данных получит статус `healthy`:

```bash
docker compose ps
```

Откройте `http://localhost`. Если порт `80` занят, запустите проект на другом порту:

```bash
FRONTEND_PORT=8081 docker compose up --build -d
```

В этом случае откройте `http://localhost:8081`. При последующих запусках с тем же портом укажите `FRONTEND_PORT=8081` и в командах `docker compose`.

Посмотреть логи, если какой-либо контейнер не запустился:

```bash
docker compose logs
```

Остановка:

```bash
docker compose down
```

Остановка с удалением данных PostgreSQL:

```bash
docker compose down -v
```

По умолчанию PostgreSQL хранится в Docker volume `postgres-data`. При первом запуске Spring Boot автоматически создаёт схему, таблицы, тестовых пользователей и демонстрационных студентов.
